Git Commands

Commands I forget
November 21, 2026 · 3 min · Javier De Carli

General Commands#

Command Description
git push -u origin <branch> Push a branch that is not linked to a remote yet
git commit --allow-empty -m "<commit message>" Creates an empty commit
git stash list List of stashes
git worktree list List linked worktrees

Revert#

flowchart LR
    A["A"] --> B["B"] --> C["C"] -->|"git revert HEAD<br/>adds a commit"| R["Revert C<br/>undoes the changes of C"]
Command Description
git revert <commit> Undoes one commit (opens the editor for the message)
git revert --no-edit <commit> Same, with the default message and no editor
git revert HEAD Undoes the last commit
git revert --no-commit <commit> Undoes the changes but doesn’t commit, so they can be reviewed or combined
git revert <oldest>~1..<newest> Undoes a range of commits, both ends included (one revert commit each)
git revert -m 1 <merge commit> Undoes a merge, keeping the branch it was merged into (parent 1)
git revert --continue Continues after fixing conflicts
git revert --abort Cancels the revert and goes back to how it was

Undo the Last Commit#

For commits that are not pushed yet. If it is already pushed, use git revert HEAD instead.

flowchart LR
    C["Last commit"] -->|"git reset --soft<br/>stops here"| S["Staged"]
    S -->|"git reset<br/>stops here"| W["Unstaged<br/>files keep the changes"]
    W -->|"git reset --hard<br/>goes all the way"| X["Deleted"]
Command Description
git reset --soft HEAD~1 Removes the commit, keeps the changes staged
git reset HEAD~1 Removes the commit, keeps the changes but unstaged
git reset --hard HEAD~1 Removes the commit and deletes its changes
git commit --amend -m "<new message>" Changes the message of the last commit
git commit --amend --no-edit Adds the staged changes to the last commit, same message
git reflog Lists where HEAD has been, to get back a commit removed by mistake (git reset --hard <commit>)

Rename a Branch#

Command Description
git branch -m <new name> Renames the current branch
git branch -m <old name> <new name> Renames another branch
git push -u origin <new name> Pushes the renamed branch and links it to the remote
git push origin --delete <old name> Deletes the old name from the remote

Setup Commands#

Command Description
git config --local user.name "John Doe" Adding name at local level
git config --local user.email "johndoe@example.com" Adding mail at local level
git config --global core.editor "code --wait" Visual Studio Code
git config --global core.editor "nano" Nano
git config --global core.editor "'C:/Program Files/Notepad++/notepad++.exe' -multiInst -notabbar -nosession" Notepad++ (Windows only configuration)

Configuration Levels#

Commands#

Command Description
git config --local -l Lists all configurations at the local level
git config --global -l Lists all configurations at the global level
git config --system -l Lists all configurations at the system level
git config -l --show-scope --show-origin Lists all configurations from every level, with the level and file of each one
git config --show-scope --show-origin --get-all user.email Shows one setting in every level where it is set; the last one is the one in use

Hierarchy levels#

Level Flag File Applies to
system --system /etc/gitconfig (Git for Windows: C:\Program Files\Git\etc\gitconfig) Every user on the machine. Needs admin/sudo to change
global --global ~/.gitconfig Every repository of the current user
local --local .git/config The current repository. Default when setting a value with no flag
worktree --worktree .git/config.worktree The current worktree only. Needs git config extensions.worktreeConfig true first, otherwise it acts as local
command git -c <key>=<value> <command> none That one command only

When the same setting is in more than one level, the most specific one wins: command, worktree, local, global, system.
