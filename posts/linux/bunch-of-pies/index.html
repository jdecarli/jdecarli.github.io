A bunch of pies

A weekend project that worked extremely well
November 18, 2026 · 4 min · Javier De Carli

I’m continuously amazed at how many perfectly usable computers are thrown to the trash, and I’m not talking about broken hardware. I’m talking about stuff that is working, perfectly well, and in some cases still supported!

This story starts many years ago (maybe around 2018) my wife was able to salvage these 3 Raspberry Pi Model 3b from the dumpster (or well… on their way to the dumpster) because she knows I’m a nerd with a tendency to adopt homeless hardware devices 🤣. Apparently they were used as thin-clients on an office and the new IT department decided to replace them with some mini Thinkpads, which I feel was a wise decision given the GUI performance is abysmal. Anyways, Raspberries (at least anything below Pi4) given they are terrible at holding any GUI 1, are not hardware meant to replace your desktop but more to act as a server, or a terminal-only box.

The Raspberry Pi 3b is from around 2016 so these mini computers were thrown away with barely 2 years in. They have multiple of USB ports, HDMI, WiFi/Bluetooth, little power source and they even still had the memory cards!. Main specs are:

So… what can we do with one of these devices?#

There are many projects that can be installed but the one that really piqued my interest was the Pi-hole project

It already became almost impossible to browse with a normal browser with no ad-blocker, so I had this feeling other devices might also be sending all sorts of data, sometimes without asking or anybody agreement. How much network bandwidth was I losing to telemetry and ads? Impossible to know, right?

This was the perfect project… plus I could dip my toes into Linux outside work.

Enter… the Pi-hole project#

The project is basically an open source DNS sinkhole. What it does is to act as a DNS for all the computers in your local network, but it hold a list of domains and provide the respective IP address only if the domain is not blacklisted (acting as a Domain Name System sinkhole)

flowchart TB
    D["Device on the network<br/>laptop, phone, smart TV"] -->|"where is ads.tracker.com?<br/>where is github.com?"| P{"Pi-hole<br/>is the domain on a blocklist?"}
    P -->|"yes · ads.tracker.com"| B["Answers 0.0.0.0<br/>the request goes nowhere"]
    P -->|"no · github.com"| U["Asks the upstream DNS<br/>e.g. 1.1.1.1"]
    U -->|real ip address| P2["Pi-hole returns the real ip<br/>and caches it for next time"]
    P2 --> C["Device connects to github.com"]

Blocked domains get 0.0.0.0, an address that leads nowhere, so the ad or tracker never loads. Everything else works as a normal DNS.

These list of domains are mostly on GitHub and are maintained by the community. Some of them are more permissive, and others more aggressive. Just be careful when going away from the default “general purpose” list because we can end up blocking some domain used for something specific (some companies will deny you certain service if their device or service cannot “phone-home”)

Apart from that it can also act as a DHCP server which was perfect because my router decided to start acting funny after 30 or 40 ip addresses and, as an added advantage of using it as a DHCP server, is that now the Pi-hole knows each which device has which ip assigned and can filter and identify which device is calling which domain, how many calls are blocked, and other useful metrics that help us see very interesting things, like certain devices that shouldn’t be calling anybody mysteriously sending data to ad or telemetry servers. 2

There’s no point in putting a tutorial or going into more details because this is very well documented.

And…#

And that Raspberry Pi 3b with the Pi-hole server has been running non-stop for 7 years… now I had to think what would be of the other 2.
